# 프리랜서 계약서·견적서 생성기 — MVP 기획/설계

> 출처: 리서치 대시보드 아이디어 #2 (조건부 추천 6/10)
> 스택 방향: **Next.js 웹앱** / 이 문서는 코드 없이 기획·설계만 정리

---

## 0. 한 줄 정의

특정 직군(개발 외주부터)의 프리랜서가 **견적서·계약서를 5분 안에 한국 표준 양식 PDF로** 만들고 공유하는 웹 도구.

차별화 = 카드가 짚은 빈틈인 **"생성 + 서명 + 세금계산서를 한 흐름으로 묶은 저가 도구 부재"**.
단, v1은 욕심내지 않고 **생성 + PDF**까지만. 서명·세금계산서는 검증 후 부착.

---

## 1. 만들기 전에: 검증 (코드보다 먼저)

최대 리스크 = "무료 대체재 많음 + 법적 정확성 부담" → **돈 낼 사람 존재 여부**를 먼저 확인.

프리랜서 10명 인터뷰 질문:
1. 지금 견적서·계약서를 **어떻게** 만드나요? (한글/워드/노션/안 씀)
2. 한 건에 **시간**이 얼마나 들고, 가장 짜증나는 부분은?
3. 월 9,900원이면 **결제 링크 누르실래요?** (의향 말고 행동)

통과 기준(예시): 10명 중 3명 이상이 "지금 결제 가능"이라고 답하면 MVP 진행.

---

## 2. MVP 범위 (v1에 들어가는 것 / 빠지는 것)

### v1에 포함 ✅
- 견적서 생성 → 한국 양식 PDF
- 계약서 생성 (개발 외주 표준 템플릿 1종) → 한국 양식 PDF
- 문서 저장(내 문서 목록), 다시 열어 수정
- PDF 다운로드 + 공유 링크(읽기 전용)
- 무료 3건/월 제한 + Pro 안내

### v1에서 빠지는 것 ⛔ (검증 후 v2+)
- 전자서명 (상대방 서명 흐름)
- 세금계산서 연동 (홈택스/팝빌 등)
- 다직군 템플릿 (디자인·마케팅 등)
- 팀/협업

## 3. 화면 흐름 (User Flow)

```
[랜딩] ──로그인──> [대시보드: 내 문서 목록]
                         │
          ┌──────────────┼──────────────┐
       [새 견적서]    [새 계약서]    [기존 문서 열기]
          │              │              │
          ▼              ▼              ▼
     [작성 폼] ───────[실시간 미리보기]───────┐
          │                                   │
       [저장]                            [PDF 생성]
          │                                   │
          ▼                                   ▼
   [내 문서 목록]                    [다운로드 / 공유 링크]
                                            │
                                            ▼
                                  [공유 링크: 읽기 전용 뷰]
```

### 화면별 상세
| 화면 | 핵심 요소 | 비고 |
|---|---|---|
| 랜딩(`/`) | 가치 제안, 샘플 PDF, "무료로 만들기" CTA | 비로그인도 접근 |
| 로그인(`/login`) | 이메일 또는 소셜(카카오/구글) | NextAuth |
| 대시보드(`/app`) | 내 문서 목록, 새로 만들기 버튼, 이번 달 사용량(n/3) | |
| 작성(`/app/new?type=quote\|contract`) | 좌측 폼 / 우측 실시간 미리보기 | 자동 저장 |
| 문서 보기(`/app/doc/[id]`) | 미리보기, PDF 다운로드, 공유 토글 | |
| 공유(`/s/[token]`) | 읽기 전용 렌더 + PDF 다운로드 | 비로그인 접근 |
| 요금제(`/pricing`) | 무료 vs Pro 9,900원, 결제 | 검증 단계엔 가짜 결제 버튼 가능 |

## 4. 데이터 모델 (초안)

```
User
  id, email, name, provider, plan(free|pro), createdAt

Document
  id, userId, type(quote|contract), title, status(draft|final)
  payload (JSON)        # 폼에 입력된 모든 값
  templateId            # 사용한 양식 버전
  shareToken (nullable) # 공유 링크용
  createdAt, updatedAt

UsageCounter            # 무료 3건/월 제한 추적
  userId, yearMonth(YYYY-MM), createdCount
```

### payload 예시 — 견적서(quote)
```json
{
  "supplier": { "name": "", "bizNo": "", "address": "", "contact": "" },
  "client":   { "name": "", "bizNo": "", "address": "", "contact": "" },
  "issueDate": "2026-06-07",
  "validUntil": "2026-06-30",
  "items": [
    { "name": "랜딩페이지 개발", "qty": 1, "unitPrice": 1500000, "note": "" }
  ],
  "vatMode": "separate",     // separate(별도) | included(포함) | none(면세)
  "memo": "결제 조건: 계약금 50% ...",
  "currency": "KRW"
}
```
- 합계/부가세는 **저장하지 않고 렌더 시 계산** (불일치 방지).

### payload 예시 — 계약서(contract)
```json
{
  "title": "소프트웨어 개발 용역 계약서",
  "partyA": { "name": "", "bizNo": "", "address": "", "signer": "" },
  "partyB": { "name": "", "bizNo": "", "address": "", "signer": "" },
  "scope": "",
  "amount": 0,
  "vatMode": "separate",
  "paymentTerms": "",
  "period": { "start": "", "end": "" },
  "ipOwnership": "client",   // 저작권 귀속
  "clauses": [ "표준 조항 ID 목록 또는 커스텀 문구" ]
}
```

## 5. 양식(템플릿) 종류 — 차별화의 핵심

"한국 세무·법무 양식 정확도"가 곧 해자. 양식은 **버전 관리되는 데이터**로 취급.

| 양식 | v1 | 비고 |
|---|---|---|
| 견적서 (표준) | ✅ | 공급자/공급받는자, 품목표, 부가세 별도·포함·면세 처리 |
| 소프트웨어 개발 용역 계약서 | ✅ | **변호사 검수 1종** — 가장 큰 신뢰 자산 |
| 거래명세서 | v2 | |
| 디자인/마케팅 용역 계약서 | v2 | 직군 확장 |
| NDA(비밀유지) | v2 | |

> ⚠️ 법적 정확성 부담 대응: v1 계약서는 반드시 **변호사 1회 검수** 후 출시.
> 화면에 "표준 참고용, 중요 계약은 전문가 검토 권장" 고지 문구 노출.

## 6. 기술 설계 (Next.js)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) | 폼·미리보기·API 한 곳, Vercel 배포 쉬움 |
| 인증 | NextAuth (카카오/구글) | 한국 프리랜서 타깃 → 카카오 우선 |
| DB | Postgres + Prisma (Supabase/Neon) | 무료 티어로 시작 |
| PDF 생성 | **서버에서 React→PDF** (`@react-pdf/renderer`) 또는 HTML→PDF(Puppeteer) | 한글 폰트 임베딩 필수(나눔/Pretendard) |
| 결제 | 토스페이먼츠 / 카카오페이 | 검증 단계엔 "결제 의향" 버튼으로 대체 가능 |
| 공유 링크 | shareToken 기반 비로그인 라우트 | |
| 호스팅 | Vercel + 관리형 Postgres | |

### PDF 한글 처리 주의
- 폰트 임베딩 안 하면 한글 깨짐 → **나눔고딕/Pretendard 폰트 파일 번들** 필수.
- 금액 표기: `1,500,000원` + 한글 병기(`일백오십만원`) 옵션이면 신뢰도 ↑.

## 7. 수익화

| 플랜 | 가격 | 한도 |
|---|---|---|
| Free | 0원 | 월 3건, 워터마크 또는 기능 제한 |
| Pro | 월 9,900원 | 무제한, 워터마크 제거, (추후) 서명·세금계산서 |

초기엔 **건당 과금 대신 구독**으로 단순화 (대시보드 추천가 그대로).

---

## 8. 로드맵

### Phase 0 — 검증 (1주)
- 인터뷰 10명, 샘플 PDF 2장(견적서·계약서) 손으로 만들어 보여주기
- 랜딩페이지 + "결제 의향" 버튼으로 수요 측정

### Phase 1 — 작동하는 MVP (1~2주)
- 견적서 생성 + PDF
- 개발 외주 계약서 1종(변호사 검수) + PDF
- 로그인, 내 문서 목록, 공유 링크, 무료 3건/월 제한

### Phase 2 — 수익화 (1주)
- 토스/카카오페이 구독 결제
- Pro 한도 해제

### Phase 3 — 빈틈 공략 (검증 후)
- 전자서명 흐름
- 세금계산서 연동
- 디자인·마케팅 직군 템플릿 확장

---

## 9. 성공/중단 기준 (정해두고 시작)

- **계속**: Phase 0에서 결제 의향 3건+ / Phase 2에서 유료 전환 10명+
- **피벗/중단**: 인터뷰에서 "무료로 충분"이 8명+ 이거나, 출시 후 한 달 유료 0명
